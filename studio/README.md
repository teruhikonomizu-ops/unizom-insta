## いつ動くか
- **①定時**：タスク `インスタ_火曜リール_夜の制作`＝**毎週月曜 21:00**（`scripts\スタジオ_火曜リール.ps1`・`conhost --headless`・WakeToRun・上限2時間）
  → 翌日（火曜）の `docs/media/<日付>-reel/` を作って push。
- 火曜 07:30 の `インスタ_火曜のリール` は、パックが用意済みなら**通知だけ**（「高品質版」と書かれる）。
  無ければ従来の自動リール（`build_reel.py`）で作り、**「夜の高品質版は作れず…（理由）」を通知に添える**＝空の週は出ない。
- 投稿は今までどおり、のみさんの「インスタ出して」の後だけ。
- 登録し直し＝`scripts\タスク登録_スタジオ.ps1`（何度実行しても同じ）。21時に電源が切れていた週は走らない（翌朝の従来リールに任せる）。

## 流れ（`scripts\studio_reel.py`）
1. ネタを選ぶ（`build_weekly.pick_topic`＝承認済み・リール優先）
2. **書き手**＝`claude -p --model opus --tools ""`（道具なし）に `STUDIO.md`＋キャプション指示書＋ネタ＋素材一覧＋最近の画風＋お手本 を渡し、
   台本（場面・字幕・読み上げ文）・場面コード（scenes.js）・Higgsfieldの指示・キャプションを **JSONの文章で** 受け取る
3. **生成係**＝`claude -p --model sonnet` に Higgsfield の生成3機能（generate_video / generate_image / jobs_wait）だけ許可。
   **動画1本（seedance 2.5・5秒・1080p・音あり＝80）＋画像2枚まで（nano_banana_pro 2k＝各2）＝1本80〜最大84クレジット**（2026-10-18 のみさん決定＝品質優先で 2.0 から切り替え。~~seedance 2.0＝45・上限60~~ は失効＝2.0も同日の見積りでは音ありで60だった）。主力モデルは `skills\higgsfield\SKILL.md` の「モデル早見」が正＝変えたら `scripts\studio_reel.py` も直す
4. 声（AivisSpeech・文ごとに 7拍/秒 にそろえる）→ 見本コマ18枚 → **確認役**＝`claude -p --tools Read`（見本コマ一覧を見るだけ）が
   はみ出し・重なり・誤読を点検し、直すなら直した JSON を返す（1回まで）
5. 全コマ書き出し（Playwright）→ BGM作曲＋ミックス → 合成（ffmpeg）→ 長さ15〜60秒・禁止語（キャプション・字幕・場面コード内の文字）を検査
6. 合格したら初めて `docs/media/<pack>/`（1.mp4・caption.txt・studio.json）を作り、ネタ帳・素材台帳・`studio/history.json`（画風の履歴）を更新
- 結果＝`_スタジオ結果.txt` の1行目（`[成功]`/`[失敗]`）。作業フォルダ＝`%LOCALAPPDATA%\unizom-studio\<pack>\`（log.txt・draft*.json・見本コマ一覧.jpg・コマ一覧_1秒ごと.jpg）。
- 制作中は `~/.claude/tasks/unizom-studio-制作中.txt` を5分ごとに更新＝夜スリープが「作業中」と判定して眠らない（終われば消える）。

## 🆕 テンポ＝「切り替えの早い型」（2026-10-17 のみさん決定・火曜リールの標準）
のみさん「リールは切り替えが早い方が刺激になって見に行く。ゆっくりだとのんびりして良くない。火曜はこういう感じでいこう」。
- 見本＝`OneDrive\デスクトップ\海外AIウォッチ\_見本_お手本の読み取り_2026-10-17\試作_インスタ縦長25秒_切り替えの早い型.mp4`（手作り・HyperFrames。ひな形＝`_tools\hyperframes\templates\fast-reel`）。
- 書き手への決まり＝`STUDIO.md`「🆕 テンポ」（1場面の中で絵を3〜5回切り替える・冒頭は打ち込みか大きな一語・畳み掛けを1回・数字は数え上げ・場面の切り替えは `cut` が基本）。
- 部品＝`lib.js`「🆕 切り替えの早い型の部品」（`cutAt` `drawCover` `countUp` `wordBox` `searchBar` `rush` `photoWall` `flash`・切り替え `cut`）。
- 🔴 **機械がテンポを測る**（`studio_reel.py` の `pace_check`）：見本コマの後に、冒頭の実写の場面と最後の場面を除いて0.25秒ごとに書き出し、108×192 に縮めて隣どうしの差を見る。
  目標＝大きく絵が変わる間隔が平均1.8秒以内・ほぼ止まっている秒が2割以下。届かなければ確認役に直させる（最大2回）。
  それでも届かない週は**止めずに作る**（結果の行に「⚠テンポ目標に届かず（…）」）。物差しは 2026-10-17 に実物で合わせた（手作りの速い見本＝0.69秒・0%／10/06 のスタジオ版＝4.17秒・36%）。
  測定の失敗（例外）でも止めない（合格扱い・ログに残す）。⚠ 限界＝写真の壁の流れや flash などの連続の動きも「大きな変化」に数える。
  あわせて、測定用のコマでも安全域（右190px・下420px）を検査し、**確認役に渡して直させる**（一瞬の通過で週は止めない＝止める判定は今まで通り見本コマだけ）。
- 🛟 **確認役の最後の直しで誤り（書き出しのエラー・見本コマの重なりやはみ出し・直しの途中の例外）が入ったら、問題の無かった前の版に戻して作る**（結果の行に「⚠確認役の最後の直しで誤りが出たので、その前の版で作った」・作業フォルダに `draft_final.json`）。速い型は直しの回数が増えるため（別の目の点検 2026-10-17 の指摘）。
- 📣 **⚠の知らせの届き先**＝`_スタジオ結果.txt` の行 → 火曜07:30 の `投稿パックのお知らせ.ps1` が `_最終結果.txt` の行に添える → `notify_chatwork.py` の `todays_note()` が **朝会への報告（OneDrive `ai記事自動\インスタ\自動投稿\_朝会への報告.txt`）に「注意: …」の1行**を足す＝のみさんが出す前に読む所。⚠「テンポを測れなかった」（見張りの故障）も同じ道で届く。~~結果の行に残すだけ~~（2026-10-17 再点検で、報告まで届いていなかったのを修正）。

## 🔴 安全の決まり
- 無人のClaudeに**ファイル操作・コマンド実行・投稿をさせない**（書く・見る・決まった数だけ生成する、の3つだけ）。権限バイパスは使わない。`--permission-mode dontAsk` で許可外は自動で拒否。
- 商品本体・ロゴ・パッケージの印刷・サイズ表記は AI に描かせない＝`stock/cutouts/`（実写の切り抜き）と `stock/index.json`（写真）を置く。
- 背景をぼかして素材を収めない（のみさん指摘）。写真は `photoCard`（白フチ）か `coverImg`（画面いっぱい）。

## 部品
| ファイル | 役目 |
|---|---|
| `STUDIO.md` | 書き手への制作指示書（画風の型・言葉の決まり・誤読対策・出力の形・部品の一覧） |
| `lib.js` | 共通部品（テロップ・字幕・背景の型・線・分解図・クレヨン・切り替え・時間割） |
| `player.html` / `render.js` | 書き出し（Playwright・1080×1920・30fps） |
| `media.py` | 声・読みの確認・BGM作曲・ミックス・合成 |
| `example/` | お手本＝2026-09-29 インソール好評発売中（script.json・scenes.js） |
| `history.json` | 最近使った画風（同じ並びを避けるため書き手に渡す） |
| `../stock/cutouts/` | 実写の切り抜き＋部位の座標（新商品の切り抜きはここへ1行足す） |
